FOUR BLOCKERS · 企业 AI 落地的真实障碍

企业用不好 AI，卡在四个地方

— 01 / 数据

数据散

数据散在几十个系统、文档和人脑里，没有一个统一入口。AI 看不到全貌，只看到你喂给它的那一份。

— 02 / 语义

语义乱

同一个"净销售额"，三个部门三种算法。字段名是 F003 这样的编码，AI 不知道该信哪个口径。

— 03 / 准确性

不敢信

企业数字错了代价极高。AI 每次现场推断出来的口径，没人敢直接拿进决策会。

— 04 / 一致性

留不下

人和 Agent 的经验随会话蒸发。换个新人、开一次新会话，同一个坑要重新踩一遍。

这四件事，没有一件能靠"换个更强的模型"解决。

ROOT CAUSE

模型每次都在
现场猜
你的业务

企业缺的不是更强的模型，而是一份持久积累、有人确认、能持续更新的企业语义。

语义是每次现场推断的、而不是持久积累的，就会同时出现四个不可接受的结果：

不一致同一个问题，两次问出两个数字
不可追溯数字回答不了"从哪来、什么口径"
不可治理没有确认、没有版本、没有回滚
不积累修正过一次，下次照样重犯

先有语义平面，才有可信的企业 AI。

Act 02 · ECP 企业上下文协议
06 / 17
ENTERPRISE CONTEXT PROTOCOL

把数据与知识，编译成统一的 LLM 语义平面

外圈 · 原始资产层（不可变）
数据库、API、文档、表格、会议纪要。只读接入，不动业务系统。
中圈 · 语义平面（ECP 资产）
硬语义层：实体 · 指标 · 关系 · 维度，可精确执行；软知识层：业务词条 · 分析模式 · 来源，可溯源。
内核 · 可信交付
数字块 + 叙述块 + 血缘 + 信任标记。数字只能来自硬语义层。
01 · INGEST
Agent 自动学
Agent 扫描资产、抽取语义并生成提案 —— 不是让业务方再做一次建模项目。
02 · CONFIRM
人拍板
业务人确认后才生效，带版本与证据。未经确认的语义不参与出数。
03 · RESOLVE
精确命中
命中已确认资产直接出数；未覆盖才回退现场推断，并留下痕迹待确认。

Act 02 · 一次问数，一次沉淀
09 / 17
MECHANISM WALKTHROUGH

同一个问题问三次，会发生什么

ROUND 01 推断 问"上月营收"—— 语义库没有命中，Agent 现场推断出数，数字标 ⚠️，同时生成一份口径提案交给人。
ROUND 02 确认 业务人确认"净销售额 = 含税金额 − 税额"，进入语义目录，冻结为 v1，并回填别名"营收 / 业绩"。
ROUND 03 命中 直接命中已确认资产出数，数字自带血缘与来源；再问"业绩"也能零摩擦命中，不再重新推断。
ROUND N 巡检 源表加了一列、口径变了 —— Lint 巡检自动发现漂移并生成新提案，人确认后语义跟上物理层，不等人发现。
同一个错只犯一次，这就是"越用越准"的工程含义。
Act 02 · 可信，源于设计
10 / 17
TRUST BY DESIGN

数字只能来自「已确认」

可信不是一句提示词，而是架构。三道机制保证企业数字敢进决策会。

GATE 01
确认门槛
AI 只提议，人拍板。未经确认的语义不参与出数 —— 这是落在工具面上的硬门禁，不是写在提示词里的软约束。
GATE 02
版本冻结
每次变更留版本、留证据引文、留操作日志。数字可追溯到字段，口径可回滚，过程可审计。
GATE 03
漂移巡检
表结构、维度值、join 路径一变，Lint 自动发现并生成新提案，人确认后生效 —— 语义永远跟得上物理层。
人在阀门上，不在流水线里：Agent 自动跑，卡住的地方变成一条待办，汇入统一收件箱。

THREE LOOPS · 从工具到队友

Agent 不是一次性的，它在三层循环里进化

真正让企业 AI 变强的，不是单次调用，而是"每次执行都留下经验，下次执行直接用"。

L1
LLM Loop
思考 → 行动 → 验证。ReActMasterAgent 让模型循环起来解决复杂任务，四道闸门守护长程执行。
L2
Agent Loop
每轮写入 → 每 10 轮反思 → 会话结束晋升长期记忆。跑过的任务变成下次的加速。
L3
业务场景 Loop
触发 → 执行 → 交付 → 沉淀 → 演化。Agent 在场景里变成真实角色，7×24 在岗。
NORTH STAR
沉淀厚度

衡量标准只有一个：一个新成员进入空间，多快能达到"老师傅"的工作水平？

资产就绪率 语义覆盖率 剧本复用率 待办响应时长 沉淀增速
