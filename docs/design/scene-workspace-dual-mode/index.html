场景空间：简单使用模式 + 运维管理模式优化

当前场景空间（/workspaces/detail）是「任务栏 + 大厅 + Agent 对话」三栏运维控制台，信息密度高、偏运营运维。本设计在不推翻现有架构的前提下，新增简单使用模式（Simple Mode）：进入空间默认只看到一个居中的对话框 + 左侧可折叠的历史任务列表；输入后切换为 vis_manus 双栏流式任务视图。运维管理模式（Ops Mode）保留全部能力并做针对性收敛。两种模式共存于同一路由，一键切换、记忆偏好。

一、两种模式的功能映射

设计核心是「同一套数据、两种信息密度」。下表梳理现有功能在两种模式下的去留与形态变化（✅ 保留 / 🔽 收纳入口 / ❌ 不显示）：

功能模块简单使用模式运维管理模式协调方式
顶部导航（工作台/任务/剧本/资产/设置）🔽 只保留空间名 + 模式切换开关，导航收进「⋯」菜单✅ 完整保留同一 header 组件，简单模式下渲染精简变体
左侧任务栏（待办收件箱 + 任务列表）🔽 只保留历史任务列表（可折叠），待办仅显示一个红点角标✅ 收件箱 + 状态 tab + 搜索 + 快捷操作复用 SceneTaskRail，简单模式传 variant="simple" 隐藏收件箱与批量操作
中间大厅（待办/动态/成长/统计）❌ 默认不渲染；通过「⋯ → 空间概览」抽屉按需打开✅ 默认视图大厅组件不变，简单模式下作为抽屉内容复用
Agent 对话区✅ 升级为主区域（对话信息流）✅ 右栏复用 AgentWorkspace 消息流与输入框组件

二、设计原则

  • 默认简单：新用户进入空间看到的是「一个能干的对话框」，而不是控制台；运维信息只在需要时出现（角标、抽屉、模式切换）。
  • 零数据孤岛：两种模式共享同一份任务/会话/消息数据，切换模式不丢上下文、不刷新页面。
  • 组件复用优先：输入框、任务列表、vis_manus 面板全部复用现有实现，新模式 ≈ 布局壳 + 现有组件的编排，降低实现成本。
  • 模式可记忆：偏好写入 localStorage（key：ws-view-mode-<workspaceId>），默认 simple；URL 参数 ?mode=ops 可强制覆盖（便于从运维入口跳转）。
  • 运维模式也减负：收件箱为空时自动折叠成摘要条；状态 tab 只显示有任务的维度；大厅增加「专注开关」一键隐藏成长/飞轮区块。

三、简单模式：页面状态流转

状态布局说明
S1 欢迎态左侧历史列表（可折叠） + 居中对话框问候语、推荐问题、快捷入口胶囊；对话框下方是模式/剧本/技能/模型选项条
S2 运行态左侧历史列表 + 中间步骤信息流（44%） + 右侧任务详情（56%）发送后对话框下沉到底部，vis_manus 双栏接管；右侧展示终端/代码/文件/交付物 Tab
S3 历史回放同 S2点击左侧历史任务回到对应会话，恢复最终态详情；底部输入框可继续追问

💡 S1 → S2 的转场：欢迎卡向上淡出，对话框平滑下移到底部并收窄为输入条，左右面板从中间「展开」——时长约 300ms，cubic-bezier(0.16,1,0.3,1)，与现有 rise-in 动画语言一致。

四、运维模式：针对性优化点

  • 收件箱减负：待办为空时收件箱区折叠为「✅ 待办已清空」摘要行，释放纵向空间给任务列表。
  • 状态 tab 智能化：全部/运行中/待介入/已完成/失败 5 个 tab 仅显示有数据的（「全部」常驻）。
  • 大厅专注开关：大厅右上角加「专注」toggle，隐藏成长卡/飞轮入口，只留待办与动态。
  • 模式切换常驻：header 右侧放分段开关「简洁 / 运维」，切换即时生效、无刷新。
