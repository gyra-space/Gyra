# ECP 企业语义资产

> ECP(Enterprise Context Platform)管的是"业务数字是什么意思、能不能信、从哪来"。
> 它把企业的指标口径、字段含义、维度取值沉淀成可复用的"语义资产",
> 让 Agent 查数据时口径统一、数字可信、来源可追溯。

## 一、ECP 解决什么问题

没有 ECP 时,Agent 查数据每次都"现场猜"字段含义和口径,结果是:
同一个"销售额"这次含税下次不含税、数字对不上、错了也不知道为什么。

有了 ECP:业务口径由 AI 提案、人来确认、版本化冻结。Agent 查数时优先命中
"已确认"的口径,保证同一个指标任何时候算出来都一样;不确定的地方会明确
标注 ⚠️,而不是蒙对。

**一句话:知识库管"文档里说了什么",ECP 管"业务数字是什么意思、能不能信"。**

## 二、四个核心概念(硬语义)

ECP 把业务语义拆成四类对象,每个都有"🟡 待确认(proposed)"和"✅ 已确认(confirmed)"状态:

| 对象 | 管什么 | 举例 |
|---|---|---|
| 实体 entity | 一张业务表是什么 | "销售订单"绑定到表 tb_so_01,字段 F003 是"含税销售金额" |
| 指标 metric | 一个业务数字怎么算 | "净销售额" = SUM(含税金额) − SUM(退款),粒度 按天/门店/商品 |
| 维度 dimension | 按什么切分、取值含义 | "销售区域":华东区=HD01/HD02,"大客户"=年采购额>500万 |
| 关系 relation | 表与表怎么关联 | 订单表.F002 = 客户表.C001(多对一) |

**只有"已确认"的对象才会被 Agent 用来产出带 ✅ 的可信数字。**

## 三、界面导览(/ecp 页面)

顶部是"北极星状态条":✅ 已确认对象数 / 🟡 待确认数 / 缓存命中率 / 兜底率。
下方 8 个标签页:

- **总览**:语义资产积累到什么程度了(各类对象数量、待办、健康度)。
- **收件箱**:确认人的工作区,处理 AI 提交的口径提案(确认/否决/改后确认)。
- **资产层**:管理 ECP 关注哪些数据源、知识库、文档。
- **硬语义**:浏览和搜索四类对象,看口径详情、版本历史、证据引文。
- **软知识**:业务词条和分析经验(供 Agent 写叙述,不参与算数)。
- **血缘图**:从"一个数字"追到"哪个表哪个字段"的全链路血缘图。
- **巡检**:系统自动体检,发现口径漂移、矛盾、长期未确认等问题。
- **设置**:确认人名单、操作审计日志。

## 四、上手:冷启动四步(首日即可完成)

1. **登记资产**:在"资产层"选择已接入的数据库数据源,点"就绪检查"确认连通。
2. **生成提案**:点"生成提案",AI 会扫描表结构,自动猜出实体/指标/维度候选。
3. **确认口径**:到"收件箱",把影响最大的 3-5 个核心口径确认掉(✅)。
4. **开口问**:回到对话,问"上周销售额",就能拿到带 ✅ 和血缘的可信数字。

## 五、日常使用

### 我是业务确认人(负责口径对错)
- 每天看一眼"收件箱",处理待确认提案。
- 提案卡片会告诉你:这数字从哪张表哪个字段来、会生成什么 SQL、是谁提出来的。
- 拿不准就"改后确认"(改成你认为对的口径再确认);不对就"否决"。

### 我是业务使用者(只想查数)
- 直接在对话里问,如"上月各区销售额环比"。
- 数字带 ✅ 表示走的是已确认口径,可放心用;带 ⚠️ 表示是 AI 现场推断,仅供参考。
- 对 ⚠️ 结果点一下就能反馈纠正(见下)。

### 修正一个口径(回写)
发现数字不对,直接在报告里或对话中说,例如"销售额要剔税"。
系统会定位到对应指标 → 生成新版本提案 → 告诉你影响范围("影响周报 3 处")→
确认人确认后,本次及以后所有报告都按新口径算。**同一个错不会犯第二次。**

## 六、它怎么越用越聪明(召回飞轮)

- 你说过的每个"说法"(如把"营收"理解成"净销售额")会被回填成别名,下次直接命中。
- 没命中的问题会被记录、聚类,定期变成新的口径提案推给确认人。
- 结果是:第一周可能一半问题要兜底,几周后绝大多数问题直接命中已确认口径。

## 七、常见问题

- **数字旁的 ✅ 和 ⚠️ 是什么意思?** ✅ = 来自已确认口径,可信;⚠️ = AI 现场推断,未经确认。
- **为什么 Agent 拒绝做某个跨表查询?** 因为两张表之间没有"已确认"的关联关系,
  为防止错误关联导致重复计数,系统会拒绝并自动生成一条关联提案给确认人。
- **改了口径,历史报告会变吗?** 历史报告保留当时口径(可追溯);新报告用新口径。
- **谁有权确认口径?** 在"设置"里维护的确认人名单内的用户。
